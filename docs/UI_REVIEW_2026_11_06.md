# iPhone-first UI review

Koop's primary device is iPhone. Android supplies the owner's historical WHOOP
reference. Apply Apple/Emil guidance within Flutter's existing design system;
retain the owner's WHOOP-inspired direction and app-style preference.

## Apple principles audit follow-up

Reference: [Apple design principles](https://developer.apple.com/design/human-interface-guidelines/design-principles/).
Applied consistent structure, clear feedback, available/selected control states,
and accessibility to the existing Flutter components; no new app dependency.

| Before | After | Why |
|---|---|---|
| Customize squeezed enlarged labels into fixed 64pt swatches; a 3.1x label rendered only about 18.4pt tall in the failing check | Choices gain width and wrap their full-size labels | Respect the user's text-size preference instead of undoing it visually. |
| Screen, navigation and section headings clipped at accessibility sizes and lacked heading semantics | Full text wraps and exposes the heading role | Preserve context and support screen-reader heading navigation. |
| WHOOP screen titles balanced a 40pt spacer against a 52pt info-action slot | Equal 52pt slots | Correct the 6pt title-centering error. |
| Metric tabs lacked selected/enabled semantics; state could be separated from an actionable label | Selection and availability share the button's semantic node; bottom tabs and swatches use it too | Announce what is selected and prevent futile activation of unavailable tabs. |
| Shared custom controls accepted touch but lacked keyboard activation/focus feedback | Tab focus, Enter/Space activation and a visible focus outline | Make navigation and actions usable with an external keyboard. |
| Reduce Motion set animation duration to zero but still shrank pressed controls | A static outline replaces press scaling | Preserve feedback without the transform. |
| Disabling a pressed action could trigger setState while the widget tree was locked | Reset pressed state during widget update and guard cancellation callbacks | Remove a reproducible framework assertion during changing UI state. |
| A floating coach disc could cover Customize controls | Customize omits that unrelated floating action | Keep the current task and its controls unobstructed. |

Validation: eight acceptance checks failed before implementation; 272 focused
checks pass after implementation, including existing navigation, switch,
dashboard, contrast, chart accessibility and large-text coverage. Scoped analysis
is clean. Real Customize renders were reviewed with synthetic settings at 390x844,
59pt top / 34pt bottom safe areas, and 1x/2x text. Existing golden images were not
overwritten. Device VoiceOver/Full Keyboard Access and performance are pending.

## Earlier typography and customization pass

| Before | After | Why |
|---|---|---|
| Manrope body text after the earlier visual pass | Owner-selected Montserrat text and Barlow score numerals, retaining readable body/caption sizes | Restore the owner's preferred family consistently across shared UI and root theme after reviewing font specimens. |
| Different Home/settings section-heading styles | Shared WHOOP-mode heading style and more readable settings labels | Give different screens the same visual hierarchy. |
| Many unrelated icon-tile colours in WHOOP-mode settings | Neutral icon tiles, with warning colours retained for destructive actions | Keep attention on labels and state rather than decoration. |
| Cigarettes always prepended above Dashboard metrics | An ordered, hideable Customize item, added at the bottom by default | Let the owner choose its place without deleting journal entries. |
| Tonight's Sleep required repeated arrow taps or dragging | Move to bottom shortcut in Home sections | Make the requested layout change one action while preserving other section choices. |
| Custom size flattened system scaling from a 1pt probe | System scaling is composed at each actual font size | Preserve nonlinear accessibility scaling. |
| Large-text layout used the same 1pt probe | Body/label sizes decide reflow | Restack based on the text people actually read. |
| Day selector squeezed between profile/streak and band | Balanced header reflows when space is insufficient | Preserve readable text and a centered day, including iPhone safe areas. |
| Binary preferences looked like ordinary On/Off rows | Adaptive switches expose one toggled semantic node | Clear affordance and one accessible action. |
| Dashboard hover lifts also applied on touch | Hover effects require a mouse-like pointer | Avoid sticky hover feedback on phones. |
| Web charts and rings ignored reduced motion | CSS transitions and chart animations respect the preference | Show changed data without unnecessary movement. |
| No wrist cigarette action or dashboard entry | Opt-in live action, editable self-reported count and latest time | Make a frequent logging task short and understandable. |
| Only a daily cigarette total | 7/30-day bar graph with logged-day coverage | Show history while keeping unlogged dates visibly unknown. |
| Corrections required opening the journal | Remove one with Undo on the app dashboard | Correct accidental entries quickly without deleting other journal data. |
| One double-tap immediately logged a cigarette | Optional second distinct double-tap confirmation | Reduce accidental entries without claiming unsupported triple-tap detection. |

Apple Design and Emil Design Engineering informed typography, immediate existing
press feedback, restrained motion and accessibility. Frontend Design informed
the visual hierarchy and copy; the explicit WHOOP reference takes precedence
over its generic aesthetic preferences. Vercel's React Native material was
reviewed for state and native UI principles. React Native components/libraries
are not introduced into this Flutter application.

The iPhone-themed widget checks cover narrow widths, large text, centered day
selection, safe areas and switch semantics. Real iPhone BLE/background behavior,
Safari interaction and SideStore installation remain to be verified after an
approved release. Desktop tests and Android installation are labelled separately.
