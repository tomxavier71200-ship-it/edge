# iPhone-first UI review

Koop's primary device is iPhone. Android supplies the owner's historical WHOOP
reference. Apply Apple/Emil guidance within Flutter's existing design system;
retain the owner's WHOOP-inspired direction and app-style preference.

| Before | After | Why |
|---|---|---|
| Montserrat body text and smaller captions | Bundled Manrope text, Barlow numerals, slightly larger body/captions | Clearer hierarchy informed by populated WHOOP screens, without new font dependencies. |
| Custom size flattened system scaling from a 1pt probe | System scaling is composed at each actual font size | Preserve nonlinear accessibility scaling. |
| Large-text layout used the same 1pt probe | Body/label sizes decide reflow | Restack based on the text people actually read. |
| Day selector squeezed between profile/streak and band | Balanced header reflows when space is insufficient | Preserve readable text and a centered day, including iPhone safe areas. |
| Binary preferences looked like ordinary On/Off rows | Adaptive switches expose one toggled semantic node | Clear affordance and one accessible action. |
| Dashboard hover lifts also applied on touch | Hover effects require a mouse-like pointer | Avoid sticky hover feedback on phones. |
| Web charts and rings ignored reduced motion | CSS transitions and chart animations respect the preference | Show changed data without unnecessary movement. |
| No wrist cigarette action or dashboard entry | Opt-in live action, editable self-reported count and latest time | Make a frequent logging task short and understandable. |

Apple Design and Emil Design Engineering informed typography, immediate existing
press feedback, restrained motion and accessibility. Frontend Design informed
the visual hierarchy and copy; the explicit WHOOP reference takes precedence
over its generic aesthetic preferences. Vercel's React Native material was
reviewed for state and native UI principles. React Native components/libraries
are not introduced into this Flutter application.

The iPhone-themed widget checks cover narrow widths, large text, centered day
selection, safe areas and switch semantics. Real iPhone BLE/background behavior,
Safari interaction and SideStore installation remain to be verified after an
approved release. Desktop tests and Android installation are labelled separately.
